## Key Question 1: Core philosophy and the layering rules

### Takeaway
Bazaar is a persistent AI software company, not an AI coding assistant. Each agent is a coworker with identity, memory, specialties and authority. Coordination happens through group chats (GCs), with no master orchestrator. Codex Alchemist is the first company run on the platform. The user set explicit rules about which system owns which job: GC as the event and decision record, Kanban as the scheduler and dependency manager, the Constellation (Mood Board) and Vault as one knowledge graph, and the server as the only place real compute and truth live.

### Inferences
- The user's rules form one design principle: the GC is the authoritative record, and every other surface (Kanban, Constellation, Vault, client UI) is a view or scheduler over it. Personality and the Soul are treated as part of the core, because they drive agent behavior.
- The server/client split is what lets the Windows and Android clients have different jobs ("build" vs "stay connected") even though they share UI code. The team file says "the use case, not the tech stack, drives the feature differences." ([Team file 2026-08-07 11:49 context](/root/.claude/uploads/c63e21e3-9139-50bc-9f48-e82954f68a61/bdf692f3-Secret_project_team_assembly-2026-10-25.md); [Zip: Bazaar.Android.md §2](/tmp/claude-0/-home-user-Bazaar/c63e21e3-9139-50bc-9f48-e82954f68a61/scratchpad/files-zip-3/Bazaar.Android.md))
