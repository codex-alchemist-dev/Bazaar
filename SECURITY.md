# Security Policy

## Status

Bazaar is pre-release. There are no supported versions yet, so no release line
is covered by security fixes. This policy describes how to report a problem so
that it reaches the maintainers privately.

## Reporting a vulnerability

Do not open a public issue, pull request or discussion about a security
problem.

Report it privately through GitHub private vulnerability reporting:

https://github.com/codex-alchemist-dev/Bazaar/security/advisories/new

This project does not accept security reports by email.

## What to include

- What the problem is, and where it is: file path, commit or branch.
- The impact you believe it has, and who could be affected.
- Steps to reproduce, or a minimal proof of concept.
- Whether you have disclosed the details anywhere else.
- The name or handle you would like credited, if any.

Do not include real credentials, API keys, personal data or private company
material in a report. If you need to show that a secret is exposed, say where
it is and redact its value.

## What to expect

We will try to acknowledge a report and keep you informed while we look at it.
While the project is pre-release we cannot promise fixed response times or fix
dates. If we decide a report is not a vulnerability, we will tell you why.

When a fix is available, we will agree disclosure timing with you and credit
you in the advisory if you wish.

## Scope

This policy covers the code and configuration in this repository. If the
problem is in third-party software that Bazaar depends on, report it to that
project as well, and tell us if it affects Bazaar.
