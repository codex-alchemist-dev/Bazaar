# Gap research overturns several DECIDED items

Seven DECIDED items break outright under the gap research and a re-read of the design docs, and several more are strained, including the Council's voting order, "Codex" in the team name and the use of free-tier models for company work; the owner needs to rule on each before implementation starts. The most concrete break is on Windows: Bazaar cannot silently replace Notepad or become the default terminal, because Windows 11 leaves the choice to the user in Settings ([distribution note](/home/user/Bazaar/research_notes/Bazaar%20remaining%20gaps%20research/distribution_os_integration.md)). Two client rules also collide with the design. Passkey sign-in needs an interactive browser page, which "no web client, ever" allows only as a read-only status page ([remote-access note](/home/user/Bazaar/research_notes/Bazaar%20remaining%20gaps%20research/remote_access_auth_push.md)), and the "stay connected" Android design cannot depend on a background socket under Android's foreground-service limits. Inside the design, the Soul doc both keeps the Passport outside the agent's VM disk and mounts it into that VM, and the DECIDED sign-up rule lets agents register on platforms that bar bot accounts. The coordination evidence neither supports nor refutes the no-orchestrator design, but it does show that the Council's stated-reasoning vote and peer-review reputation are exposed to sycophancy and gaming. The cost model puts a six-agent team at about **$177 a month typical, $26 light and $1,035 heavy**, on assumed inputs, with the Sonnet escalation lane as the largest single lever. Every licensing, trademark, platform-terms and law item below needs counsel or vendor confirmation before release.

## Seven DECIDED items break under the new evidence

The Windows client doc calls for detachable windows that "register as the OS default handler (replacing Notepad / the default terminal)" ([Bazaar.Windows.md](/home/user/Bazaar/docs/deep-dives/Bazaar.Windows.md), Section 1). The distribution note finds that Windows 11 blocks apps from writing the UserChoice registry key, and that a driver-level guard now enforces this. Its sources are secondary: an aggregator, a 2024 news report and Mozilla's developer docs, because the Microsoft policy page itself was not read. The realistic route is to register file-type and terminal capabilities, deep-link the user to Settings, and let the user choose. The default terminal goes through a Windows Terminal console handoff that nobody has spiked ([distribution note](/home/user/Bazaar/research_notes/Bazaar%20remaining%20gaps%20research/distribution_os_integration.md), Key Question 2). The same Windows doc marks terminal control libraries as **RESEARCHED**, but the earlier feasibility report calls the "production-grade ConPTY" claim unsupported ([feasibility report](/home/user/Bazaar/reports/Bazaar%20stack%20feasibility%20research.md), decisions table). The owner should amend the Notepad line rather than argue with the platform.

The Server doc says "No web *client*, ever, on any client," and allows only "a small read-only status page" that "never shows chat, code or Vault content" ([Bazaar.Server.md](/home/user/Bazaar/docs/deep-dives/Bazaar.Server.md), Section 1). The remote-access note recommends passkeys for the owner's browser sign-in, and it says that choice holds "only if the owner accepts a sign-in page." ASP.NET Core passkeys are scoped to browser authentication, and Microsoft says the library "isn't intended as a general-purpose WebAuthn library" (**verified**, Microsoft Learn). A sign-in page is interactive, so it breaks the rule as written. The RFC 8628 device-code flow has the same problem on the approving device, because its verification URI is a web page; the remote-access note's pairing design therefore has to keep the approval step inside a native client (**inference**). A related question sits in the Windows doc, which DECIDES that Monaco runs "embedded in a scoped WebView2 island." A native client that hosts a web editor is not a web client by the letter of the rule, but the owner should say so explicitly. The Avalonia cross-platform WebView sits under the paid Accelerate tier, and no source shows Monaco running inside any Avalonia WebView (**secondary**, [feasibility report](/home/user/Bazaar/reports/Bazaar%20stack%20feasibility%20research.md)).

The Android doc is built around "Stay connected": the unfolded layout shows a notification ticker, and the owner wants to "watch agents work" from the phone ([Bazaar.Android.md](/home/user/Bazaar/docs/deep-dives/Bazaar.Android.md), Sections 1 and 3). The remote-access note reports that Android 15 and later cap a `dataSync` foreground service at **6 hours in any 24-hour period**, after which the service must stop, and that Doze defers network access (**verified**, Android developer pages as summarised). It also reports that FCM depends on Google Play services (**verified**). The distribution note disagrees. It recommends `dataSync` as the WebSocket keep-alive and calls the 6-hour figure "unverified," because it read only the Android 16 behaviour-change page and not the foreground-service timeout page. The two notes cannot both stand, and the timeout page should be re-read before the design relies on either. On either reading, the always-on socket cannot be the only delivery path. The design needs a content-free push as a wake signal, which the app follows with a fetch over the authenticated connection.

The Soul doc contains two DECIDED statements that pull against each other. Section 1 says the Passport "Must live outside the agent's VM disk." Section 2 says "Soul data (memories, reputation, the Passport, anything durable) must live outside the VM disk entirely ... mounted in as one scoped folder" ([Bazaar.Soul.md](/home/user/Bazaar/docs/deep-dives/Bazaar.Soul.md), Sections 1 and 2). An agent that can read the mounted folder can read the Passport. The threat-model note calls this the most important internal conflict and recommends that the Passport and audit log are never under any mounted path, with only the memory mounted read-only ([agent security threat model](/home/user/Bazaar/research_notes/Bazaar%20remaining%20gaps%20research/agent_security_threat_model.md), Section 7 and Conflicts). The DECIDED text needs to be rewritten to match that rule.

The Bazaar core doc DECIDES that "Agents can sign up for external services (dev forums, GitHub, Stack Overflow, social media) using their Soul identity" ([Bazaar.md](/home/user/Bazaar/docs/deep-dives/Bazaar.md), Section 2). Several platform rules cut against this. The GitHub Terms, as summarised by a fetch tool, say that accounts "registered by 'bots' or other automated methods are not permitted," which makes this a **secondary** finding that needs the primary text. Google's terms bar "creating fake accounts or content" (**verified**, primary). Hacker News bans generated text and automated posting (**verified**, primary guidelines). The Linux kernel allows AI-assisted contributions only with a named human who takes responsibility (**verified**, primary). Reddit's public API is reported to end by March 2027, but that rests on a TechCrunch article (**secondary**). The policy note could not read the current Stack Overflow, Discord or Roblox rules (**unverified**). The DECIDED clause should be restated as human-created accounts with a named human sponsor, and each platform should be checked before any post. The threat-model note also places CAPTCHA, phone and ID steps in a human-only tier, which the clause must respect.

The core doc keeps GCs "append-only / immutable as a record ... never destructively purged," and on 2026-10-24 the owner added that "messages can be edited, but every version is kept" ([Bazaar.md](/home/user/Bazaar/docs/deep-dives/Bazaar.md), Section 2). GDPR Article 17 gives erasure grounds, and Article 17(3) carves out exceptions for freedom of expression and for archiving or research where erasure would seriously impair those aims (**verified** text, gdpr-info.eu). The backup note proposes crypto-shredding: encrypt each person's fields under a per-person key and destroy the key on request. Its sources are vendor and blog pages (**secondary**), and it found no decision on whether crypto-shredding is legally sufficient. Backups also keep old keys until they expire, so the design has to purge key copies too ([backup note](/home/user/Bazaar/research_notes/Bazaar%20remaining%20gaps%20research/backup_dr_soul_portability.md), Section 6). The record rule and erasure can coexist only if personal fields live in per-person encrypted payloads and the DECIDED wording changes. This is a **counsel** question, not a finding of law.

The core doc contradicts itself on model routing. Charles has "Routing: `auto/cheap` only," and the junior swarm uses "`auto/*`-routed specialists." Two lines later the same document DECIDES that "No agent uses a global `auto/*`" ([Bazaar.md](/home/user/Bazaar/docs/deep-dives/Bazaar.md), Section 3). Because the rule is stated and then broken in the same table, the owner must choose which line survives. The pricing note also finds that the DeepSeek name in the whitelist, `deepseek-v4-flash`, is retired and now served as DeepSeek-V4.1-Flash-1017 (**verified**, DeepSeek pricing page as summarised), so the whitelist needs the new ID.

The coordination note adds evidence against two DECIDED mechanisms. The Council DECIDES that "whole team votes with stated reasoning." Matched-budget studies report that majority voting matches or beats debate on reasoning tasks, and that agents abandon correct answers after reading peers' reasoning (**secondary**, several arXiv summaries; the note did not open the primary PDFs). The inference the note draws is that each agent should record an independent vote first, and only then see the tally and the reasons, with at most one round. Agent self-preference bias is **verified** at the abstract level (arXiv 2410.21819). The DECIDED reputation mechanism, in which "delegation shifts toward proven strengths" from peer evaluation, is exposed to review gaming: 2026 reports say LLM reviewers can be inflated by rewriting toward reviewer preferences (**secondary**, news coverage of Baumann et al. and an arXiv preprint). The note recommends anchoring reputation to hard outcomes such as CI results, reverts and human acceptance. The no-master-orchestrator rule is not refuted. Anthropic's **verified** research system beat a single agent by 90.2% on an internal eval, but it spent about 15 times the chat tokens, and Anthropic calls most coding tasks a poor fit for multi-agent work. Cognition's critique is a vendor opinion. The harness note says Cognition's description of Claude Code subagents looks outdated, while the coordination note treats it as current. No source tests a GC-only design.

## Risks that could stop a build, not just slow it

The threat-model note finds that every Bazaar agent holds all three legs of Meta's "Rule of Two" by default: it reads untrusted content, it can reach private data, and it can act outside the system (**verified**, Meta AI blog; Willison's "lethal trifecta" post). Its sources for the attack cases are mostly secondary. The Rules File Backdoor is **verified** from the vendor's own research post, but the GitHub MCP issue injection, the Nx "s1ngularity" malware and the 2026 MCP CVE counts are secondary or unverified. Because GCs are shared and append-only, one poisoned message stays in every agent's context permanently. The note's P0 controls are session taint tracking, a reader/actor split, no secrets inside any VM, default-deny egress and a host-side audit log. None of these is built, and no DECIDED item requires them. The P0 list also depends on an Identity Service that Bazaar.md marks **PROPOSED** and CLAUDE.md says not to build on without asking.

The cost model rests on an Anthropic constraint that is not optional. A Start-tier organisation has a **$500 monthly spend cap**, and once it is reached the API returns a 429 with no `retry-after` header, so retries fail until the month resets (**verified**, Anthropic rate-limit page). The Work-Life Simulation replaces rate limits in the design, but it cannot replace this hard stop. The qualifying spend for the Build and Scale tiers is not published, so the owner cannot plan the move. Whether the Haiku 5.5 price step at 100,000 tokens applies to the whole prompt or only the excess is unverified. Claude 4.7 and later tokenizers produce about 30% more tokens for the same text (**verified**). The observability note adds that the OpenTelemetry GenAI conventions are still in Development status, so attribute names must be pinned, and that the Aspire dashboard accepts unauthenticated OTLP unless API-key auth is set, so it must stay on localhost (**secondary**).

Several agent-design choices have no measured evidence. The harness note found no edit-format data for Haiku 5.5 or DeepSeek V4; its Aider data is from 2024 and 2025 models. The coordination note found no measured miss rate for a cheap gatekeeper, which means the Skimmer Bouncer's savings and its risk of silently dropping messages are both unproven. No source measured how often agents fake success, or how well LLM judges catch it. The harness note's fake-success checks (test counts must not drop, test files must not change without a flag, builds run from clean) are inferences.

The distribution risks are mostly licence fit and terms. SignPath's free programme for open-source projects requires every component to be under an OSI licence without commercial dual-licensing, and the project must already be released in the form signed (**secondary**, terms as quoted by search snippets). Avalonia's paid tiers charge **EUR 299 and EUR 899 per seat per year** and carry no open-source exemption (**verified**, Avalonia pricing as read in the feasibility report). A signed build that includes a paid component therefore cannot qualify. The notes give two different prices for XPF, EUR 55,000 and EUR 89,000, and the owner should get a quote. Velopack's documented model covers the desktop client, not a Windows Service, so the server needs its own installer track. The Azure Artifact Signing monthly prices did not render, and its eligibility for individuals is unknown (**unverified**). Microsoft's CAL and licensing position for agent VMs, and whether Windows 11 Pro may run 24/7 as a host, are unresolved and need written answers from Microsoft or a reseller.

The backup note turns the RPO and RTO figures into design proposals, not measurements. It proposes about one hour of data loss at most and about one day to rebuild the NUC, and it notes that no restore timing has been measured. Losing the Passport master key means every GitHub App key, OAuth grant and API key must be rotated. A restore that rolls the GC log back to an older backup discards later events, which conflicts with append-only (**inference**). For Postgres, `pg_dump` alone cannot support point-in-time recovery, and WAL archiving must be tested before the first base backup (**verified**, PostgreSQL 18 docs). pgBackRest and WAL-G are Linux-first, and Barman's Windows status is secondary and unclear.

The platform and law items all need counsel. The EU AI Act's Article 50 disclosure duty is reported as applying from 2 August 2026 (**verified**, a mirror of the text), but one secondary source reports a December 2026 grace period, and the notes do not resolve the conflict. Article 50(4) requires disclosure of AI-generated public-interest text unless there is editorial control. California's bot-disclosure statute (BPC 17941) applies to commercial and election deception, with a platform exclusion, and its 2019 text is only secondary. The Philippines' Data Privacy Act reaches processing linked to the Philippines, and the note lists criminal penalties (**verified**, statute text as summarised). CAN-SPAM's per-email penalty is $53,088 (**verified**, FTC guide). GDPR and PECR were not verified at all. Remote access also needs a licence check: Tailscale's free Personal plan is "for non-commercial use," and a company tailnet on a custom domain is treated as business use (**verified**, Tailscale pricing). Standard is $8 per user per month.

Naming is a risk, not a decision. The notes find "Codex" to be the highest-risk element, because OpenAI's Codex is a prominent AI coding agent. The DECIDED team name "Codex Alchemist" and the GitHub org `codex-alchemist-dev`, which the Server doc says is already created, sit directly on that overlap. The naming note's search found no Codex-specific trademark guidance, and it could not reach the USPTO, EUIPO or WIPO registries. "Vault" collides with HashiCorp Vault and "Constellation" with ShiftinBits' code-intelligence product (both **secondary**). "Bazaar" is an existing VCS name (GNU Bazaar, whose fork Breezy is documented on Wikipedia; **verified**) and a crowded term in AI-agent marketplaces. The note made no trademark finding for any name. The note also says the public NuGet `Bazaar.*` prefix is nearly open (one personal package uses it), but prefix reservation was not checked.

## Confirmed items the gaps can build on

Several findings are solid enough to build on, and most come from primary pages. .NET 10 LTS is supported until November 2028, and Microsoft documents hosting an ASP.NET Core worker as a Windows Service with `AddWindowsService()` ([feasibility report](/home/user/Bazaar/reports/Bazaar%20stack%20feasibility%20research.md), "What held up"). PostgreSQL 18 has a Windows installer, PostgreSQL 14 reaches end of life on 12 November 2026, and pgvector builds on Windows with MSVC (**verified**, feasibility report). The vault note lists the pgvector Windows build as unverified, so the feasibility report's primary-page read is the better source. Valkey is "not officially supported on Windows," and ParadeDB's pg_search binaries cover Debian, Ubuntu, RHEL and macOS only (**verified**). Microsoft says Garnet has been "extensively tested to work equally efficiently on both Linux and Windows," though its StackExchange.Redis compatibility is unverified.

Anthropic's terms say developers building products "should use API key authentication" and that Anthropic "does not permit third-party developers ... to route requests through Free, Pro, or Max plan credentials" (**verified**, Claude Code legal page as read in the feasibility report). The pricing page's current rates are **verified** as summarised: Haiku 5.5 at $0.10 input and $0.50 output per million tokens, Sonnet 5.5 at $2 and $10, Opus 5.5 at $4 and $20, Fable 5.1 at $10 and $50. Cache writes cost 1.25 times base for five minutes, cache reads 0.1 times base for most models, and the Batch API gives 50% off ([pricing note](/home/user/Bazaar/research_notes/Bazaar%20remaining%20gaps%20research/pricing_cost_model.md), Key Question 1). The Start tier's Haiku 5.5 limits are 1,000 requests per minute, 2,000,000 input tokens per minute and 400,000 output tokens per minute (**verified**). Cache reads do not count toward input-token limits for most current models, which matters for bursty group chat.

On the messaging and identity side, RFC 8628 gives the device-pairing semantics, including rate-limiting user codes (**verified**). ntfy's default is open access, and its `deny-all` option is recommended for a private instance (**verified**). UnifiedPush lists self-hostable distributors (**verified**). Cloudflare Tunnel is outbound-only and needs no inbound ports (**verified**), though its WebSocket fit is not confirmed. On the Android store side, a personal developer account created after 13 November 2023 must run a closed test with at least 12 testers for 14 continuous days before production access (**verified**, Google Play Console help). Android 14 and later require each foreground service to declare a type (**verified**).

The security and data notes rest on verified primaries as well. Meta's Rule of Two and Willison's lethal-trifecta framing are both **verified**, and the CaMeL arXiv abstract reports 77% of AgentDojo tasks solved with provable security against 84% undefended. NuGet's source mapping is limited to restore, install and update, and a package already in the global packages folder bypasses it (**verified**). Git's `merge=union` driver can scramble line order, so Markdown should use the default text merge (**verified**, git docs). The Anthropic multi-agent research post is **verified** on its own numbers, and the MAST failure taxonomy of 14 failure modes across three categories is **verified** from the arXiv abstract. The Hacker News rule against AI-generated text is **verified**.

## The cost model holds near $177 a month, on assumed inputs

The pricing note models a six-agent team with a lane split of 25% Haiku architect, 5% Sonnet escalation, 20% Gemini research, 20% DeepSeek V4 Pro implementation, 15% DeepSeek Flash boilerplate and 15% junior agents on free tiers. Its three scenarios are 40, 150 and 400 work items a day, with 3, 5 and 8 model calls per item, and cache hit rates of 0.5, 0.7 and 0.8. Every one of these inputs is an assumption; the note says no usage has been measured, and the owner should replace them with the NUC's own logs before any budget decision.

| Scenario (work items per day) | Base prices | Upper bound (Gemini step-up, DeepSeek peak) |
|---|---|---|
| Light (40) | $25.58 per month | $42.97 |
| Typical (150) | $176.76 per month | $297.70 |
| Heavy (400) | $1,035.30 per month | $1,749.30 |

On the Claude lane alone, the typical scenario costs about **$54.17 a month** and the heavy scenario about **$316.56**, both under the $500 Start-tier cap. The largest single driver is the Sonnet escalation lane. At 5% of work items it is about 24% of typical spend, and moving those calls to Haiku would save about $40.60 a month typical (about $235 heavy), before any quality cost. Putting that lane on Opus roughly doubles the typical lane to about $85.73. Fable on that lane would push the heavy scenario's escalation lane to about $1,186, and heavy use on Opus or Fable would exceed the Start-tier cap. Prompt caching at a 70% hit rate roughly halves per-call cost on every paid lane, but the hit rate is unmeasured, and a 5-minute cache may be too short for group-chat cadence. The note also understates Anthropic cost by about 11 to 12%, because it charges cache misses at the base input price and not the write premium. Two cautions matter beyond the numbers. Google's free Gemini tier is labelled "Used to improve our products: Yes," and the plan sends 15% of work to free-tier juniors, so the owner must decide whether that data can carry company code or GC content. And the note's Skimmer Bouncer cost assumes a gatekeeper that has no measured miss rate.

## Decisions the owner must make

1. **Default apps.** Accept that Bazaar registers its file and terminal capabilities and deep-links to Windows Settings, and drop "replacing Notepad" as a silent outcome in the Windows doc. Decide whether the console-handoff spike goes ahead.
2. **Sign-in surface.** Decide whether an interactive owner sign-in page, such as passkeys, is allowed as an exception to "no web client, ever." The note's recommended default is no, with pairing approved inside native clients only.
3. **Monaco.** Decide whether an embedded Monaco editor in a native client counts as a web client, and whether a cross-platform editor requires the paid Accelerate tier.
4. **Android connectivity.** Adopt push-wake with content-free notifications, choosing FCM (which depends on Google Play services) or UnifiedPush with ntfy for a Google-free path. Stop treating a continuous socket as the background delivery path. Require the foreground-service timeout page to be re-read to settle the `dataSync` dispute.
5. **Passport placement.** Adopt the rule that the Passport and the audit log are never mounted into an agent VM, with only memory mounted read-only, and amend Soul Section 2.
6. **Agent sign-up.** Restate the self-sign-up clause as human-created accounts with a named human sponsor. Keep Hacker News excluded, and hold Stack Overflow, Reddit, Discord, Roblox and Godot until their current primary rules are read.
7. **Public posting.** Approve the four approval tiers from the policy note, under which any new public post or outreach email needs a human's approval, and obtain counsel's view on the EU Article 50 role split.
8. **Erasure.** Approve per-person encryption with crypto-shredding for personal fields, subject to counsel, and decide whether personal data in edited GC messages may keep every version.
9. **Soul sharing.** Keep the Soul Marketplace out of v1, or write an explicit carve-out to the rule that a company's Souls are never shared cross-instance.
10. **Rule of Two.** Adopt session taint tracking and the reader/actor split as DECIDED requirements before any agent reads email or stranger issues, and decide whether the Identity Service becomes DECIDED.
11. **Model routing.** Remove `auto/*` from Charles and the junior swarm, or amend the DECIDED rule. Update the DeepSeek whitelist IDs, and decide whether Fable stays off until its availability is confirmed.
12. **Free-tier data.** Decide whether free-tier lanes, including Gemini's free tier and free aggregator models, may see company code or GC content. The notes' default is no.
13. **Gateway.** Confirm that FreeLLMAPI does not carry Anthropic traffic, given that the Server doc says it "maps Claude names to its free pool" and that its provider-terms review is self-assessed. Keep Pro and Max routing and `auto/subscription` off every key, and obtain counsel's view on any Gemini OAuth lane.
14. **Claude budget.** Decide whether the escalation lane runs on Haiku or Sonnet, whether Opus or Fable is allowed given the $500 Start-tier cap, and whether to pursue Build-tier qualification.
15. **Council and reputation.** Rewrite the Council as an independent vote followed by stated reasoning, and anchor reputation to hard outcomes rather than LLM reviews.
16. **Coordination bet.** Accept GC-only coordination as an untested bet, with a measured pilot that tracks vote flips, loop counts and the gatekeeper's miss rate, or name a fallback coordinator now.
17. **Naming.** Decide whether "Codex" stays in the team name and the GitHub org, which already exists. Commission clearance searches for Bazaar, Vault, Constellation and Soul through counsel.
18. **Licensing and signing.** Settle the AGPL and Apache split, DCO or CLA, whether SignPath's OSI-only rule is the signing route, and whether to buy Avalonia's Accelerate or XPF tiers. Counsel and Avalonia must confirm the terms.
19. **Windows licensing.** Obtain written Microsoft answers on CAL treatment for agent VMs and on Windows 11 Pro as a 24/7 host, then choose Standard, Datacenter or a mix.
20. **Email back ends.** Decide whether the built-in SMTP/IMAP server stays a v1 back end, given that Bazaar.md's own research caveat says a home-hosted MTA usually fails PTR and port-25 requirements (a RESEARCHED item in Bazaar.md, Section 2). Counsel must review the Philippine, CAN-SPAM and GDPR/PECR exposure.
21. **Backup and keys.** Approve the RPO and RTO targets as proposals to be tested in a drill, choose an offsite store, and set custody for the two keys (the backup repository and the Passport master key).
22. **Distribution.** Limit Velopack to the Windows client, give the server its own installer track, sideload the Android APK for the owner first, and open a Play closed test only if Play is needed.
23. **Remote access.** Choose between Tailscale Personal, Standard or self-hosted Headscale before any coworker joins. Use Cloudflare Tunnel only after a WebSocket test.
24. **Wire format and observability.** Fix the Server doc's cell that says Protobuf is DECIDED while the cell also says "reopened," and match CLAUDE.md's OPEN. Approve the Aspire standalone dashboard on localhost only, with content capture off and usage stored in Postgres.

## Conclusion

The gap research changes the question from "can Bazaar be built" to "what is allowed on which surface," and most of the blockers are platform rules, Windows defaults and internal contradictions rather than missing code. Three of the seven outright conflicts can be settled with a sentence in the design docs: the Notepad line, the Passport mount and the `auto/*` contradiction. The rest need a decision, and two of them, sign-in and erasure, shape the architecture as well as the policy. The notes also disagree in places that the owner should not accept without a check. The foreground-service timeout, the pgvector Windows build, the status of OpenAI's Codex README (verified by the harness note, treated as secondary by the naming note) and the EU Article 50 date are each reported differently by different sources, and each needs its primary page re-read.

The largest remaining unknowns are measurable, and they should be measured before the budget or the agent design is fixed. Those are the prompt-cache hit rate, the escalation split, the cheap-model edit format, the gatekeeper's miss rate and the fake-success rate. The three spikes already recommended in the feasibility report (Postgres, pgvector and Garnet on the NUC image; a throwaway-repository GitHub App test; and a WebView and Monaco spike) should be joined by an Android push-wake spike and a host-side egress test in a nested VM. Everything legal, licensing, trademark and terms-related in this report is a question for counsel or the vendor, and none of it is legal advice.
