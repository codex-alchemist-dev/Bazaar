# Windows hosting and vendor terms break Bazaar pillars

Bazaar's .NET core holds up, but three load-bearing pillars do not survive contact with primary sources. A Windows-only host cannot run Valkey or ParadeDB pg_search natively, Anthropic's current terms prohibit the subscription-credential lane that the gateway plan depends on, and GitHub's rules bar agents from creating their own accounts and conflict with the fork-and-PR flow. The UI and hardware plans are also off course: the official Avalonia WebView sits under a paid Accelerate licence rather than XPF, Intel NPUs run through OpenVINO rather than DirectML, and Roblox Studio requires an open GUI session that headless agent VMs cannot provide. The confirmed foundations are .NET 10 LTS, Windows Service hosting, native PostgreSQL 18 with pgvector, and Microsoft's Windows-tested Garnet as a Valkey substitute. The owner now has to decide the server data stack, the Claude and model-supply policy, the GitHub identity model, the WebView licence budget, the Roblox host, and the Windows licensing position. Every licensing or terms item needs counsel or vendor confirmation before anyone relies on it. The source notes are dated 24 October 2026, and the design documents themselves were not in the folder, so each verdict tests the claim as the notes quote it.

## Hard blockers sit in the Windows host and vendor terms

**Valkey and pg_search do not run natively on a Windows host.** Valkey's installation guide says it is "not officially supported on Windows" and points Windows users to WSL ([Valkey installation docs](https://valkey.io/topics/installation/); primary, `data_layer_windows.md` section 4). The upstream native-Windows request closed in May 2025 with a maintainer comment that "there are no plans to provide compiled binaries for Windows at this time" ([valkey-io/valkey issue #92](https://github.com/valkey-io/valkey/issues/92); primary). ParadeDB's prebuilt pg_search binaries cover Debian, Ubuntu, RHEL and macOS only, and its extension docs say nothing about Windows ([ParadeDB extension docs](https://www.paradedb.com/docs/deploy/self-hosted/extension); primary, `data_layer_windows.md` section 3). A Windows-only NUC therefore needs WSL2, Docker or a Linux VM for either component, or a replacement. The note's native alternative is PostgreSQL 18 with pgvector, plus Microsoft Garnet for the cache role, which Microsoft says has been ["extensively tested to work equally efficiently on both Linux and Windows"](https://microsoft.github.io/garnet/docs) (primary). Garnet's compatibility with StackExchange.Redis and its persistence behaviour on Windows are unverified. The design-doc view that pg_search is "not a blocker" is an unreviewed opinion. AGPL-3.0 obligations attach if an installer bundles pg_search, and that is a counsel question.

**Anthropic's terms rule out routing subscription credentials.** Anthropic's Claude Code legal page says developers building products, including with the Agent SDK, "should use API key authentication," and that Anthropic "does not permit third-party developers ... to route requests through Free, Pro, or Max plan credentials on behalf of their users" ([Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance); primary, fetched 2026-10-24, `ai_gateway_models.md` section 3). The note ranks this as the highest-risk item in the gateway plan. Secondary press reports describe server-side blocking from 9 January 2026 and an April 2026 change that moved third-party tool use onto extra-usage billing. Those reports were not checked against Anthropic announcements. OmniRoute's `auto/subscription` tag should be disabled on every Bazaar key. Google's terms for Gemini CLI and Antigravity OAuth were not verified from a Google primary source, and the claim that family accounts share one quota pool is forum speculation. Counsel must review any subscription configuration before Bazaar is published.

**GitHub's rules conflict with the agent identity and fork-PR model.** GitHub's Terms say, in the fetched summary, "You must be a human to create an Account. Accounts registered by 'bots' or other automated methods are not permitted" ([GitHub Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service); secondary, summarised by the fetch tool, wording to verify, `github_community_presence.md` section 1). Agents therefore cannot register themselves, and a human must create each account and hand over an App or token. The installation-token documentation says tokens "cannot be granted access to repositories that the installation was not granted access to" ([GitHub App installation authentication](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/authenticating-as-a-github-app-installation); summarised). The forks endpoint requires the App "installed on the source account with access to the source repository" ([Forks REST API](https://docs.github.com/en/rest/repos/forks); primary). Both contradict the design doc's assumption that no installation on the upstream repo is needed. The only support for opening issues on uninstalled public repos is one 2025 community answer from a user labelled "Maintainer," who is not identified as GitHub staff (unverified). Secondary-limit rules of 80 content-creating requests per minute and 500 per hour cap posting throughput, and the Acceptable Use Policy bans "excessive automated bulk activity." Maintainer policy is tightening: secondary reports say several large projects ban or restrict AI-generated contributions, and none of those reports were checked against project primaries.

**The WebView plan is contradicted and carries licence cost.** The design doc says the most polished WebView integration sits under Avalonia XPF. The XPF overview does not mention WebView at all ([Avalonia XPF welcome](https://docs.avaloniaui.net/xpf/welcome); primary). Avalonia's NativeWebView documentation places the control under Avalonia Accelerate and says the package requires the Accelerate licence ([NativeWebView docs](https://docs.avaloniaui.net/accelerate/components/webview/nativewebview); search snippet, `avalonia_clients.md` Q4). The Accelerate price, tier and platform coverage were not found. The free options are community packages. WebView2.Avalonia lists Windows and macOS only, and Avalonia.WebView claims all four targets, with maturity and licence unverified. No source shows Monaco running inside any Avalonia WebView on any platform. The Avalonia core is MIT, but the paid tiers charge per seat: Plus at EUR 299 per seat per year and Pro at EUR 899 per seat per year. Pro adds the Rich Text Editor, Tree DataGrid, Markdown Viewer and PDF Viewer, and the pricing page states no open-source exemption ([Avalonia pricing](https://avaloniaui.net/pricing); primary). The XPF enterprise price conflicts between notes. `cicd_repo_licensing.md` reads EUR 55,000 from the official page, while `avalonia_clients.md` could reach only a snippet and an aggregator's EUR 89,000. Avalonia sales and counsel must confirm all of it.

**Roblox Studio needs an open GUI session.** Roblox's official Studio MCP documentation says Studio must be open and the MCP server is enabled inside it. The server runs locally over stdio, next to Studio ([Roblox Studio MCP docs](https://create.roblox.com/docs/studio/mcp); primary, `engine_plugins.md` key question 2). The same page warns that connected clients can read and modify content in open places, and it describes no authentication mechanism. Roblox's official computer requirements list Windows 10 and 11 and macOS. That came only from a search snippet, because the requirements page returned 403 (`hyperv_agent_vms.md` key question 8). No source reached shows Studio running in a headless Server Core VM, so the design's Studio-in-agent-VM premise is unsupported. The design doc's claim that Studio has no official Linux client rests on a DevForum quote and the same unverified snippet.

**Cloud Hypervisor has no documented Windows-host path.** Cloud Hypervisor's README lists KVM and Microsoft Hypervisor hosts, with Linux-based host tooling ([Cloud Hypervisor README](https://github.com/cloud-hypervisor/cloud-hypervisor/blob/main/README.md); primary). Firecracker requires `/dev/kvm` on Linux and does not run on Windows ([Firecracker getting started](https://github.com/firecracker-microvm/firecracker/blob/main/docs/getting-started.md); primary). The design's "sub-second boot" claim has no source (`hyperv_agent_vms.md` key question 7). The documented Windows-side options are Hyper-V itself and WSL2 nested inside a Hyper-V VM, which Microsoft lists as a supported scenario ([Nested virtualization](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/nested-virtualization); primary).

**Licensing is unresolved, not yet proven fatal.** Microsoft's US list prices are $1,176 for a Windows Server 2025 Standard 16-core licence and $6,771 for Datacenter, with a 16-core minimum per physical server ([Microsoft Windows Server pricing](https://www.microsoft.com/en-us/windows-server/pricing); [Microsoft licensing](https://www.microsoft.com/en-us/licensing/product-licensing/windows-server); both primary, neither dated). The note's arithmetic puts the Standard-to-Datacenter crossover near 11 Windows Server VMs. Microsoft says Windows Server CALs are required "for every user or device accessing a server," and no source addresses whether an agent VM counts. Whether Windows 11 Pro may run 24/7 as a server host is unverified, and the note treats it as not clearly allowed. Stripped Tiny11-style images carry EULA risk according to secondary sources. Evaluation media runs for 180 days, and the rearm count is secondary-only. These points need written answers from Microsoft or an authorised reseller.

## What held up: .NET 10, Windows services and native Postgres

The .NET target holds. Microsoft lists .NET 10 LTS as supported until November 2028, and .NET 8 LTS and .NET 9 STS both reach end of support in November 2026 ([Microsoft .NET releases and support](https://learn.microsoft.com/en-us/dotnet/core/releases-and-support); primary, `dotnet_server_hosting.md` key question 1). The Worker Service with `AddWindowsService()` is documented, including the `--contentRoot` install pattern and the Event Log default of Warning ([Host ASP.NET Core in a Windows Service](https://learn.microsoft.com/en-us/aspnet/core/host-and-deploy/windows-service?view=aspnetcore-10.0); primary). A hard kill can skip `StopAsync`, so in-flight agent turns must persist their own state. Crash-restart recovery settings are not on that page and remain unverified.

On data, PostgreSQL 18 has an EDB-built Windows installer tested on Windows Server 2022 and 2025, and PostgreSQL 14 reaches end of life on 12 November 2026 ([PostgreSQL Windows installers](https://www.postgresql.org/download/windows/); [PostgreSQL versioning policy](https://www.postgresql.org/support/versioning/); primary, `data_layer_windows.md` section 1). pgvector builds on Windows with MSVC and `nmake /F Makefile.win` ([pgvector README](https://github.com/pgvector/pgvector); primary). No prebuilt Windows binary was confirmed, so each PostgreSQL minor upgrade means a rebuild. Valkey's BSD-3 licence is verified from its COPYING file, and Redis's own post confirms the March 2024 move to SSPL and the AGPLv3 option from Redis 8 ([Redis AGPLv3 announcement](https://redis.io/blog/agplv3/); primary). The design doc's "RSAL" wording remains unverified.

Client and tooling facts also hold up. Avalonia 12.1.4 is the latest stable release, dated 9 October 2026 ([Avalonia releases](https://github.com/AvaloniaUI/Avalonia/releases); primary). The Android backend rebuild is real, but its performance figures are vendor claims without test conditions ([Avalonia 12 announcement](https://avaloniaui.net/blog/avalonia-12); vendor). Android Tier 1 covers only Android 16, with Android 12 to 15 at Tier 2 ([Avalonia supported platforms](https://docs.avaloniaui.net/docs/supported-platforms); primary). Microsoft Agent Framework 1.0 shipped on 3 April 2026 under MIT ([MAF 1.0 announcement](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/); primary). Its orchestrator model conflicts with Bazaar's rule that the conversation coordinates, so the note recommends taking libraries selectively. That conflict is an inference from the feature list. The official Anthropic C# SDK provides an `IChatClient` adapter, and the third-party `Anthropic.SDK` package is not affiliated with Anthropic ([Anthropic C# SDK docs](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/csharp); primary). Windows ML maps NPUs to OpenVINO for Intel, QNN for Qualcomm and VitisAI for AMD, with DirectML only as a legacy GPU provider ([Windows ML: accelerate AI models](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/accelerate-ai-models); primary). Godot's headless CLI, including `--export-release`, `--check-only` and `--script`, is documented, and unknown flags fail silently ([Godot command-line tutorial](https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html); primary). Godot C# projects cannot export to web ([Godot C# docs](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/index.html); primary).

Two infrastructure choices are supported by primary pages. Cloudflare Email Routing's documented limits (200 routing rules per domain, 25 MiB inbound) and Resend's official pricing (Free at 3,000 emails a month and 100 a day; Pro at $20 for 50,000) support inbound and outbound mail over HTTPS without home-hosted port 25 ([Cloudflare Email Routing limits](https://developers.cloudflare.com/email-routing/limits/); [Resend pricing](https://resend.com/pricing); primary, `email_identity_accounts.md`). Woodpecker's Windows agent supports only the Local backend, and Docker there needs WSL2 or Windows containers ([Woodpecker supported platforms](https://woodpecker-ci.org/docs/administration/installation/supported-platforms); primary). The note therefore rates it a poor fit for executing agent-written code.

## Unverified risks that could still move the budget

Android text input is the most likely mobile blocker. Avalonia documents IME support, but the soft-keyboard and caret issues found date from 2024, and one comment reports Korean input unresolved. No current bug count was found (`avalonia_clients.md` Q2, unverified). Fold and unfold behaviour, 120 Hz scheduling, and Windows UI Automation or Android TalkBack accessibility are all unverified (Q6, Q9). Terminal control candidates have no confirmed licence or maturity, so the design's "production-grade ConPTY" claim is unsupported (Q5).

On the NPU, no .NET API for enumerating execution providers was verified. Intel's driver-to-OpenVINO matrix conflicts between sources (2026.2 against 2026.3.1), and no official Intel tokens-per-second figure exists. OpenVINO warns that compiled NPU blobs are not guaranteed portable across driver and runtime versions, but the wording of that warning is unverified (`local_npu_inference.md`). The Android QNN throughput figures come from one developer's repository, and the Whisper real-time factor of 0.09 to 0.13 is anecdotal.

On the model side, OmniRoute's own page gives inconsistent provider counts, and its CVE and default-password claims are unverified. Caveman's telemetry is on by default and sends recent prompts to a cloud service once enabled ([Caveman repository](https://github.com/JuliusBrussee/caveman); self-described, `ai_gateway_models.md` section 6). NVIDIA's hosted endpoint is governed by trial terms that were not fetched. Google's quota pooling between Antigravity and Gemini CLI is undocumented, and Gemini CLI quota now applies per user per day ([Gemini CLI quota and pricing](https://geminicli.com/docs/resources/quota-and-pricing/); primary).

Agent-runtime questions remain largely open. The sandbox for agent tool execution was not researched, and the note calls it the largest hole. The Skimmer Bouncer's cost and accuracy have no evidence behind them. Mem0's benchmark gains are self-reported. Orleans is MIT-licensed, but its version and streams support were not verified, and Temporal .NET version numbers conflict across sources.

External platform pressure is also material. Reddit's reported public-API end in March 2027 rests on a TechCrunch search snippet. Godot's reported ban on autonomous-agent submissions is secondary-only, and Stack Overflow's policy could not be fetched. On CI, GitHub postponed the self-hosted runner platform charge with no new date, but some third-party pages still describe it as live (`cicd_repo_licensing.md` key question 1). Rules on CAPTCHA, phone verification and scam replies are a counsel question, and the note recommends forbidding CAPTCHA-solving services outright.

## Decisions the owner must make

1. **Server data stack.** Choose native PostgreSQL 18 with pgvector and Postgres full-text search, with LISTEN/NOTIFY or in-process channels for fan-out. Add Garnet only if a benchmark shows the need. The alternative is accepting WSL2, Docker or a Linux VM for Valkey and pg_search. The choice depends on whether BM25-grade ranking justifies a Linux VM and an AGPL review.

2. **Claude lane and model supply.** Confirm that the Claude lane uses Anthropic API keys only, and remove Pro and Max routing and `auto/subscription` from every key. Decide whether any Gemini OAuth lane exists at all, which needs counsel. Whitelist provider model IDs checked against live catalogues, keep Fable off until its availability is confirmed, and budget a paid DeepSeek fallback with 429 backoff.

3. **GitHub identity.** Have a named human create every account and App. Run the two throwaway-repo tests, issue creation on an uninstalled public repo and fork-then-PR, before the design is locked. Decide whether agents post to repositories they do not own, given maintainer bans and the rate and acceptable-use limits.

4. **WebView and UI licence.** Choose among Avalonia Accelerate (price still needed), a community WebView package (maturity unverified), or WebView2 on Windows with a separate Linux and Android plan. Decide whether Monaco is a hard requirement, since no source shows it working. Decide whether any Pro-tier control is worth its per-seat cost. Keep XPF out of the public repository until counsel and Avalonia confirm the terms.

5. **Roblox placement.** Choose between running Studio only on the human Windows desktop host, with agents limited to headless Luau static checks, and deferring Roblox automation out of version 1. Either way, get counsel review of Roblox Creator terms and of automation, because the official Studio server lets connected clients write to open places.

6. **Hypervisor topology.** Choose between one nested WSL2 VM per agent and two VMs per agent, and benchmark both. Drop Cloud Hypervisor on the Windows host unless the design adds a Linux host. Decide whether Hyper-V-isolated containers are worth a spike.

7. **Windows licensing position.** Obtain written answers from Microsoft or an authorised reseller on CAL treatment for agent VMs, on Windows 11 Pro as a 24/7 host, on per-VM licensing when the host is not Windows, and on evaluation media. Then choose Standard, Datacenter, or a mix weighted toward Linux guests. Exclude Tiny11-style images.

8. **On-device ML per platform.** On Intel, target the OpenVINO execution provider through the Windows ML catalogue, with driver 32.0.100.5540 or later, and exclude 32.0.100.4300, 4509 and 4512. On Android, choose among ONNX Runtime QNN, LiteRT and GenieX. Keep Windows speech-to-text on the CPU until NPU execution is tested.

9. **Wire contracts.** Resolve the Server doc's "DECIDED" Protobuf line. The note recommends shared C# contracts with source-generated System.Text.Json, unless a non-.NET SDK or plugin author is planned.

10. **Identity, mail and CI.** Buy an owned domain and drop the xx.kg subdomain. Use Cloudflare Email Routing and Resend, with no home-hosted mail server. Run public-repo CI on hosted runners only, keep self-hosted runners in the private repo for trusted refs, drop Woodpecker, and confirm GitHub's runner billing.

11. **Licence and autonomy limits.** Choose AGPL-3.0 or Apache-2.0 for the server and clients, with Apache-2.0 for the SDK and contracts if the note's split is adopted, and choose DCO or CLA. Forbid CAPTCHA-solving and SMS-rental services, drop autonomous scam-baiting, and disable Caveman telemetry and routing. Each licence or terms item here needs counsel review.

## Conclusion

The notes show that .NET itself is the least risky part of the stack. The failures occur at boundaries: a Windows host where Linux-first components were assumed, third-party terms that prohibit the automation pattern, and GUI-bound tools placed in headless VMs. Those boundaries should be designed around now rather than patched later. Three small spikes would settle most of the open questions. The first is PostgreSQL 18, pgvector and Garnet on the actual NUC image, with a StackExchange.Redis compatibility check. The second is a throwaway-repository GitHub App test covering issue creation and fork pull requests. The third is a WebView and Monaco spike on Windows and Android before any Accelerate purchase.

The stack question has also become a policy question. The owner's choices on the Claude lane, the GitHub identity model and Roblox placement shape the architecture more than any library choice does. Several gaps are recorded as open in the notes, including the agent sandbox, the gatekeeper evidence and the Android device behaviour, and those should stay open in the plan until they are tested.
