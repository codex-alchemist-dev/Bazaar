# Spike S10: Default-app handoff (Windows)

Branch: `spike/S10` (nothing was built; the check is a registry script run and removed). Design source: `docs/design/35-spikes-plan.md`, `docs/design/28-windows-client.md` (OS integration, Local terminal), doc 41 section 4.10.
Runner: Claude on the owner's PC. Findings feed: doc 28 (OS integration, Local terminal), Windows doc s1 and s4.

## Question
Default-app handoff: file-type and terminal registration; `ms-settings:defaultapps` link; handoff to the built-in Bazaar.Windows terminal (C31).

## Pass criteria (fixed before the first run)
Plan text: "Bazaar is selectable in Settings; handoff opens the built-in terminal; no UserChoice write (fail: deep link only)." Time-box 2 d.

## Time-box
2 d. Not expired.

## Method
Windows 11 Pro build 10.0.26300, x64, owner's PC. A throwaway per-user registration, all under HKCU, with a private extension so no real default was touched:
- ProgID `BazaarS10Spike.File` with `shell\open\command`, and `.bzs10\OpenWithProgids`.
- Capabilities at `HKCU\Software\BazaarS10Spike\Capabilities` (ApplicationName, FileAssociations for `.bzs10`) and `HKCU\Software\RegisteredApplications`.
- `ms-settings:defaultapps?registeredAppUser=Bazaar%20S10%20Spike` launched through the shell.
- `AssocQueryString` read for `.bzs10`; `FileExts\.bzs10\UserChoice` checked before and after.
- `HKCU\Console\%%Startup` read only. It was not written.
Everything was removed afterwards and checked absent.

## Result
**inconclusive.** Per-user registration works without any UserChoice write, and Windows resolves the registered command, so the "no UserChoice write" criterion holds for file types. Two criteria are not shown:
- "Selectable in Settings": the owner's approval dialog for viewing the Settings window was declined in this session, so I did not look at the page. The deep link launched, but I did not confirm that the entry appears. A person should open it and look.
- "Handoff opens the built-in terminal": not tested. The machine's console and terminal delegation already point at Windows Terminal (`DelegationConsole` and `DelegationTerminal` under `HKCU\Console\%%Startup` are set), and changing them is a system setting that this spike does not write. A terminal handoff needs a COM server that implements the console handoff interface, which does not exist yet because the Calcinato terminal is not built. That is a build prerequisite, not a negative result.

## Consequence
No DECISIONS-LOG entry yet. Doc 28 stays as written: the installer registers per-user ProgIDs and capabilities and never writes UserChoice; the default-terminal role stays gated on S10. To close S10: (1) a person confirms the Settings entry; (2) the terminal handoff COM server exists, then test it on a throwaway Windows user account, per doc 28 Testing. Whether an unpackaged per-user install can appear in the terminal choice list at all is not established here and is the main risk.
