# Spike S5: Orleans one-agent-per-grain vs plain hosted service, 20 idle agents

Branch: `spike/S5` (code stays there; only this record reaches main). Design source: `docs/design/35-spikes-plan.md`. Decision it feeds: `docs/design/06-agent-runtime.md`, "Base choice".

## Question
Does Orleans (one grain per agent) beat a plain hosted service with a per-agent inbox and lease, for 20 idle agents, on the 06 criteria: (1) removes lease and recovery code, (2) keeps no state outside Postgres, (3) does not lose on idle memory, (4) works on Windows hosting? The plan's row also asks for wake latency and Windows and Linux parity.

## Pass criteria (fixed before the first run)
The 06 criteria are numbered here in the order they appear in 06 "Base choice": 1 lease and recovery code removed; 2 no state outside Postgres; 3 idle memory; 4 Windows hosting. The plan's wording "Orleans wins criteria 1 and 4 without losing 2 or 3" is read with that numbering.

What this spike can measure, and the rule for each:

| Item | Measured here | Rule |
|---|---|---|
| 3. Idle memory, 20 agents | Yes: working set and private bytes after 10 s idle and a full GC | Orleans loses if its median working set is more than 1.5 x the hosted median |
| Wake latency (plan row) | Yes: warm wake, caller to turn complete, 300 wakes per run | Orleans loses if its median p95 is above 50 ms |
| 4. Windows hosting | Yes, on Windows 11 only | Orleans wins if all three Orleans runs exit 0 with no error output on Windows |
| 1. Lease and recovery code removed | No: a timing spike cannot show it. Recorded as a design-review item | Not measured |
| 2. No state outside Postgres | No: design-review item | Not measured |
| Linux parity (plan row) | No, unless a Linux run is added | Not measured |

Result rules, fixed now:
- **fail**: Orleans loses on item 3 or on wake latency, or any Orleans run errors. Consequence: the plain hosted service stays as the base (06, "Base choice").
- **pass**: only if every measured item is not-losing AND items 1 and 2 are evidenced AND a Linux run passes. This run cannot show items 1, 2 or Linux, so a pass is not reachable from this run alone.
- **inconclusive**: no fail condition is met, but items 1, 2 or Linux parity are not evidenced. This is the expected outcome of this run if the measured items are not-losing.

## Time-box
2 days of effort (plan row). The timed runs take about a minute in total. Expiry records `inconclusive`.

## Method
- Code: `spikes/S5/` (`S5.csproj`, `Program.cs`) on branch `spike/S5`. Each run is one process.
- Hosted variant: `BackgroundService` with one unbounded `Channel` inbox and one `SemaphoreSlim` lease per agent, one consumer loop per agent. The turn is trivial in-memory work. Lease and inbox are in memory, not Postgres, so the hosted cost is a lower bound (a Postgres lease adds round trips and memory use).
- Orleans variant: Orleans 10.4.0 (`Microsoft.Orleans.Server`, MIT licence per the NuGet nuspec), one grain per agent with `IGrainWithIntegerKey`, single silo in the same process, `UseLocalhostClustering`. The turn is the same trivial work. Grains are activated by a warm-up call per agent, then idle for 10 s before measuring.
- Wake sequence: seeded random agent per wake (seed 42), 300 sequential wakes, latency measured from the caller's call to the turn's completion. Warm wakes only; cold activation is in the warm-up and is not timed.
- Environment: Windows 11 Pro 10.0.26300 (x64), 24 logical CPUs, 97.5 GB RAM, .NET SDK 10.0.401, runtime 10.0.13. PostgreSQL: not used (see the hosted-variant note). Linux: not run.
- Build: `dotnet build spikes/S5/S5.csproj -c Release`, run from outside the repo because `global.json` pins SDK 10.0.402, which is not installed. The spike project turns off the repo's central package management and strict analysers so it stays inside `spikes/S5`.
- Command per run: `dotnet spikes/S5/bin/Release/net10.0/S5.dll --mode hosted|orleans`.

## Runs
Three runs of each variant, alternating (hosted, orleans, hosted, orleans, hosted, orleans). Report median and spread.
