# Spike S11: Local terminal control on ConPTY (Windows) and PTY (Linux client)

Branch: `spike/S11` (code stays there under `spikes/S11/`; only this record reaches main). Design source: `docs/design/35-spikes-plan.md`, `docs/design/28-windows-client.md` (Local terminal), `docs/design/30-linux-client-and-packaging.md` (section 2, PTY backend).

## Question
Local terminal control on ConPTY (Windows) and PTY (Linux client). Agent VM terminals are server-streamed and not tested here (C31).

## Pass criteria (fixed before the first run)
Plan text, verbatim: "Shell, resize, colour and Ctrl-C correct on both; licence OSI-compatible for the OSI-only build (C23) (fail: own terminal widget)."

Operational definitions, fixed before the first run:
- Shell: `cmd.exe` and `pwsh` each start under the pseudo console; a command's marker output appears in the output stream.
- Resize: after `ResizePseudoConsole` to 100x30 and then to 132x40, `mode con` (cmd) and `$Host.UI.RawUI.WindowSize` (pwsh) report the new size.
- Colour: the child emits ESC[31m, ESC[38;5;196m (256-colour) and ESC[38;2;255;0;0m (truecolor), each followed by text and ESC[0m; pass when the output stream contains the parameter sequences `31`, `38;5;196` and `38;2;255;0;0` in SGR form. ConPTY re-encodes VT output, so the check is for the SGR parameters, not byte equality.
- Ctrl-C: `ping -t 127.0.0.1` runs in cmd and in pwsh; byte 0x03 is written to the input pipe; within 10 s the ping process exits and the shell returns a prompt that runs `echo ALIVE` successfully.
- Clean shutdown: `ClosePseudoConsole` returns, the shell process exits, and no shell or ping process started by the harness remains 5 s later.
- Time from process creation to first output byte is recorded in each run (informational, no threshold; reported as median and spread).
- Licence: each candidate library's licence is read from its NuGet metadata or repository and must be OSI-approved or a permissive licence compatible with an AGPL-3.0 build. A candidate that is not OSI-approved fails.
- Overall result: pass only when the ConPTY checks pass, the licence check passes and the Linux PTY half has also been run and passes. With only the ConPTY half run, the result is inconclusive, not pass, even if every ConPTY check passes.
- Fail consequence (plan): own terminal widget. A failed licence or ConPTY check for the chosen approach reopens the terminal library choice; the local terminal is not built on an incompatible licence.

## Time-box
2 d (plan). Hard stop at 2 d of work.

## Method
Windows (ConPTY) half below; the Linux PTY half follows under "Linux PTY half".

- **Environment.** Owner's PC: Windows 11 Pro 10.0.26300, x64, 24 logical CPUs. Harness built with the .NET 10 SDK targeting `net10.0`, run on .NET 10.0.13 (the repo now targets .NET 11; the harness does not depend on that).
- **Harness.** `spikes/S11/Spike.S11.Conpty/` on `spike/S11` (commit `70b12ef`). It is an own thin P/Invoke wrapper over kernel32 with no third-party code: `CreatePipe`, `CreatePseudoConsole`, `ResizePseudoConsole`, `ClosePseudoConsole`, `STARTUPINFOEX` with `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`, `CreateProcessW`. It drives `cmd.exe` and PowerShell 7 through the five checks defined above (SHELL_ECHO, RESIZE, COLOUR, CTRL_C, SHUTDOWN).
- **Licence check.** No library is used, so there is no third-party licence to read. This leaves the library choice (own wrapper versus a terminal-emulation component) open; the licence criterion is satisfied trivially for the wrapper and is not evidence about any candidate library.
- **Raw output.** `spikes/S11/results/` on `spike/S11`.

Findings during the trial:
- **Ctrl-C was ignored when the host had Ctrl-C disabled.** In the first trial, writing 0x03 to the input pipe did not stop `ping -t`, left `ping.exe` running and the shell unresponsive (`trial-before-harness-fixes.txt`, CTRL_C fail in both shells). Children inherit the "ignore Ctrl-C" disposition of the process that creates the pseudo console. Calling `SetConsoleCtrlHandler(NULL, FALSE)` in the host before creating the child fixes it (`diag-ctrlc-after-fix.txt`). A real terminal host must do the same.
- **Pwsh start-up is slower than cmd.** Prompt after `CreateProcess` returned is about 300 ms for pwsh and about 55 ms for cmd; first output byte is about 13 ms for both.

## Result
**pass for both PTY mechanisms; the terminal-widget and library choice stays open.** (Before the Linux half ran, this read inconclusive, as the pre-registered rule required.) All ConPTY checks pass in all three runs (shell, resize, colour, Ctrl-C and clean shutdown, for both `cmd.exe` and `pwsh`, no orphaned `ping.exe`). The Linux PTY half has now run and passes (10 of 10 checks in each of three runs, bash and dash), so the pass rule fixed before the first run is met: ConPTY passes, Linux PTY passes, and the licence check holds because neither harness uses any third-party code. This says nothing about which terminal-emulation component or widget to ship.

What this does not show: any terminal-emulation or rendering component (the harness reads the VT stream and checks SGR parameters, it does not render); behaviour under a GUI host (no Avalonia in the loop); older Windows builds (only 10.0.26300 tested); shells other than cmd and pwsh 7.

## Consequence
- The Windows ConPTY mechanism meets the criteria on the tested build, so the plan's fail consequence (own terminal widget) is not triggered by the Windows half.
- The host must clear the inherited Ctrl-C ignore flag (`SetConsoleCtrlHandler(NULL, FALSE)`) before spawning a pseudo console; this belongs in doc 28 (Local terminal) as an implementation note. Not edited here; the main session decides.
- Linux PTY half done (see below): doc 30 section 2 can rely on libc P/Invoke with no third-party PTY library.
- Open: choice of terminal-emulation component and its licence against the OSI-only build (C23).

## Linux PTY half

Run 2026-10-25 in the cloud container; harness `spikes/S11/Spike.S11.Pty/` on `spike/S11` (commit `83df4c4`), results `spikes/S11/results/linux-run{1,2,3}.txt`. The pass criteria above apply unchanged.

### Method (Linux)

**Harness.** `spikes/S11/Spike.S11.Pty` (net11.0, Linux). It mirrors the Windows harness's check names and output format (`CHECK|<shell>|SHELL_ECHO|RESIZE|COLOUR|CTRL_C|SHUTDOWN`, `TIMING`, `SUMMARY`).

- The pty is created with `posix_openpt`, `grantpt`, `unlockpt` and `ptsname_r`. The window size is set with `ioctl(TIOCSWINSZ)` on the master.
- The shell is started with `posix_spawn` and `POSIX_SPAWN_SETSID`, with signal defaults and an empty signal mask. The child opens the slave (without `O_NOCTTY`) as its stdin, which makes the slave its controlling terminal, then `dup2`s it to stdout and stderr. This avoids a custom `fork` in managed code.
- Output is drained by a polling reader thread. The reader is stopped before the master is closed, which hangs up the slave and sends SIGHUP to the session.
- Process checks read `/proc/<pid>/stat` and count live processes whose session id equals the shell's pid.
- Shells: `/usr/bin/bash --noprofile --norc -i` (bash 5.2) and `/bin/sh -i` (dash). zsh is not installed in the container and was not tested.
- Checks: marker echo (`echo S11_RESULT_$((6*7))` must produce `S11_RESULT_42` in output, not in the typed echo); resize 80x25 to 100x30 and 132x40, read back with `stty size`; colour SGR 31, 38;5;196 and 38;2;255;0;0 through `printf`; Ctrl-C (0x03 written to the master) stopping a foreground `sleep 30`, with no sleep left and the shell still running a command; shutdown (close master) ending the shell within 5 s with no process left in the session.
- Each shell is spawned fresh for every run. Timings are one sample per shell per run.

**Environment, Linux half (this container).** Ubuntu 24.04.5 LTS, kernel 6.18.44-fc-v153, x86_64, 4 logical CPUs, 15 GiB RAM, glibc 2.39. .NET runtime 11.0.0-rc.2.26504.105 (SDK 11.0.100-rc.2). Shells: bash 5.2, dash (`/bin/sh`).

**Environment, Windows half (reference, from the PC result files).** Microsoft Windows NT 10.0.26300.0, x64, 24 logical CPUs, .NET runtime 10.0.13 (not 11, as the spike was built for net10.0). RAM is not recorded in the result files.

**Build note.** The `spike/S11` branch's `global.json` pins SDK 10.0.402, which is not installed in this container; `origin/main` pins 11.0.100-rc.2. The harness was built from a directory outside the repo so that SDK resolution used the installed 11.0 SDK. `global.json` was not changed.

### Result (Linux)

**Linux half: pass (for the PTY-control part of the criterion).** On bash 5.2 and dash, all checks passed in all three runs:

- **Shell:** marker echo appeared in output on both shells (`S11_RESULT_42`).
- **Resize:** `stty size` reported the requested size after each change (`want 100x30 got 100x30; want 132x40 got 132x40`, cols x rows).
- **Colour:** SGR 31, 38;5;196 and 38;2;255;0;0 arrived unmangled on both shells.
- **Ctrl-C:** a foreground `sleep 30` was running, 0x03 stopped it, no sleep was left in the session, and the shell ran a follow-up command.
- **Shutdown:** closing the master ended the shell within 5 s with no process left in its session. The raw wait status was 1, meaning the shell was terminated by SIGHUP. The harness did not have to kill it.

Ctrl-C working implies the slave was the controlling terminal of the new session. This is the evidence that the `POSIX_SPAWN_SETSID` plus open-slave approach works.

Not done: zsh (not installed). No check of the Linux desktop terminal widget. This is a headless pty test, not a rendering test.

**Licence (Linux half): OSI-compatible for this half.** The harness uses only its own P/Invoke declarations into the system C library (glibc `libc`). It contains no third-party code and adds no library dependency. glibc is supplied by the operating system and is not redistributed with Bazaar.

**The overall criterion's fail clause ("own terminal widget") is not answered by this spike.** This spike did not check the Avalonia terminal widget, its licence, or whether Bazaar needs its own widget. Anyone relying on this result for the widget decision needs a separate check.

### Consequence (Linux)

For the DECISIONS-LOG (the main session writes it; this section does not edit that file):

- Local PTY control on Linux is viable with the platform's own libc P/Invoke (`posix_openpt`, `posix_spawn` with `POSIX_SPAWN_SETSID`, `ioctl(TIOCSWINSZ)`), with no third-party terminal library needed for the PTY layer. This is evidence for the Linux client's local terminal and for the "no own terminal widget" branch of the criterion, but it does not decide the widget.
- The widget/licence question stays open until someone checks the Avalonia terminal widget's licence against the OSI-only build (C23) and decides whether an own widget is needed.
- Windows (ConPTY) is recorded in PR #47; this section only adds the Linux half.
- The `spike/S11` branch's `global.json` (SDK 10.0.402) does not match `origin/main` (11.0.100-rc.2). This was not changed here and should be resolved on the branch separately.
