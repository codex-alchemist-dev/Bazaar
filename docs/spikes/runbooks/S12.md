# Spike S12 runbook: Monaco in a WebView

Runbook for the owner. Code stays on branch `spike/S12`; only `docs/spikes/S12.md` (the filled record) reaches main. Design source: `docs/design/35-spikes-plan.md`.

## 1. Question

Can Monaco load offline from bundled assets in a free WebView, WebView2 on Windows and WebKitGTK on Linux, with typing, IME, paste and the theme working? This is a gate for the Avalonia decision as a whole (C26, DECISIONS-LOG round 5).

## 2. Pass criteria

Fixed before the first run; do not edit after running. Copied from the plan's S12 row.

Pass rule (as written): Monaco loads offline from bundled assets; typing, IME and paste work; theme applied; HWND fallback recorded if composition fails. Per platform: each platform is judged against the same pass rule. The per-platform checks are the steps in section 7 (Windows steps 4 to 9, Linux steps 11 to 12). The spike passes only if both platforms pass (reading of doc 30, see open question 2).

## 3. Fail consequence and fallback

Plan fail row: AvaloniaEdit native editor, and the Avalonia decision is reopened.

- Composition fails on Windows: record it, then run the HWND route (free route D, direct WebView2 HWND host, doc 28 option D). Record the HWND result separately. Its status is open question 1.
- Any fail on either platform: the editor falls back to AvaloniaEdit (MIT), and the Avalonia decision is reopened (C26; doc 27 Conflicts 1; doc 30 Risks 1). This spike does not decide a migration.

## 4. Time-box

3 d per the plan. Hard stop. Expiry records `inconclusive`. Any extension needs owner approval. Record start and stop times in the record. Open question 3 covers units and scope.

## 5. Prerequisites and environment

Free routes only: no paid Avalonia components (C23), no paid WebView or editor licence. Avalonia `NativeWebView` (Accelerate) is excluded.

Before run 1, confirm that the licence of each package used (WebView2 SDK or WebView2.Avalonia, the Linux WebKitGTK host package, Monaco) fits the OSI-only build. Doc 28 says these are unverified and need counsel. If a licence is not confirmed, stop and ask the owner; the time-box keeps running.

Needed:
- Windows desktop with the WebView2 Runtime; Linux desktop with WebKitGTK.
- .NET 10 SDK (project rule) and Avalonia 12.1.4 as named in doc 27, pinned in the spike project.
- A pinned Monaco release (MIT). The version is open question 6.
- No database. No keys or secrets are needed, and none go into git.

Record in the record's Method section, per platform:
- Windows build number; WebView2 Runtime version.
- Linux distribution and version; kernel; WebKitGTK version.
- Monaco version; Avalonia version; .NET version.
- GPU and display scale.
- Keyboard layout and input method (IME) used for the IME test.
- How the offline condition was set and confirmed.

## 6. Safety rules

- The time-box is a hard stop. S12 has no spend; no paid tier, component or service is used.
- Spike code is throwaway, under `spikes/S12/` on branch `spike/S12`, and is not shipped.
- Android is out of scope: Monaco is unsupported on mobile (plan S12 row; doc 30). The native Android surface is S27.
- Avalonia.Headless does not cover the WebView (doc 28 Testing), so the desktop checks are by hand. Feel needs owner sign-off (plan Testing section).
- Monaco is embedded in a native client. It is not a web client, and no page is served to a browser as a client.

## 7. Steps

Windows (WebView2)

1. Create branch `spike/S12` from the base the owner names (open question 13). Record the commit SHA.
2. Bundle Monaco as offline assets: copy the pinned release into the spike project as content files. No CDN and no network fetch. Record the Monaco version.
3. Host Monaco in WebView2, first with composition embedding (doc 28 first design). Load the bundle through a non-file origin, because Monaco web workers do not load from `file://` (research note). The mapping method is open question 15.
4. Offline: disable the network adapter, start the app, open a fixed sample file. Pass: Monaco renders the editor from the bundle. Record how no network was confirmed.
5. Typing: type a fixed ASCII string into the sample file. Pass: the text appears exactly as typed, with no dropped or doubled characters. Record the mismatch count.
6. IME: switch to the input method in the record, compose the fixed IME test string (open question 4), convert and commit. Then compose a second string and cancel it with Escape. Pass: composition shows inline in Monaco; the committed text equals the test string; cancelled text leaves nothing. Owner judges feel.
7. Paste: copy the fixed paste text (open question 4), including non-ASCII characters, and paste with the platform's standard paste action (open question 12). Pass: the pasted text equals the clipboard text.
8. Theme: apply the theme payload built from the test tokens (open questions 5 and 6). Pass: the editor background and foreground show the token colours. Record whether a reload was needed; this is observed only (open question 10).
9. Composition fallback: if step 6 fails (no composition, or composition lost), record the failure, then repeat steps 3 to 8 on the HWND route (free route D). Record each result separately. Pass on the HWND route is open question 1.
10. Write the Windows result line (route used: composition or HWND).

Linux (WebKitGTK)

11. Host Monaco in WebKitGTK through the route fixed before run 1 (open question 8), using the same bundle and the same non-file origin rule. Run steps 4 to 8 on that host, with the same pass rules. Run on the session type fixed in open question 9.
12. IME: use the input method framework installed on the desktop (open question 4). Pass as in step 6. Record the framework name and version.
13. Write the Linux result line. If Linux fails, do not run an HWND route; it is Windows only.

14. For each step (all runs), write the observation in the record and mark pass or fail. Do not change a criterion after the first run.

## 8. Three runs

The three runs are per platform: three runs on Windows and three on Linux, six in total. Each run is a fresh app start and repeats steps 4 to 8 (Windows) or 11 to 12 plus 4 to 8 (Linux). Steps 1 to 3 are done once per platform.

Measure per platform: pass or fail for each criterion, the environment from section 5 for each run, and the observation notes. The plan sets no numeric threshold beyond pass or fail, so there is no timing median or spread. Ready time and memory are recorded only if measured (open question 10).

## 10. Consequence

The main session writes the DECISIONS-LOG entry; the owner approves the wording.

- Both platforms pass (composition): new entry citing C23 and C26. Avalonia decision stands. Record the WebView route and its licence per platform. Unblocks 27 (Monaco behind `IEditorHost`, theme generator), 28 (Windows host), 30 (Linux editor option). Doc 30 open question 9 stays with the owner.

## 11. Open questions

1. Does an HWND-route pass count as a pass when composition fails? The plan says only "HWND fallback recorded".
2. Does a Linux-only fail reopen the whole Avalonia decision? Plan and doc 30 say yes; the research note's decision tree says a Windows pass keeps Avalonia. Conflict, not resolved here.
3. Is the 3 d time-box in calendar or working days, and does it cover both platforms?
4. Which input method and fixed IME test string, and which fixed paste text (including non-ASCII)? Not in the docs.
5. Which theme tokens and format for the test? Doc 27 says the theme format is OPEN (its Q3).
6. Which pinned Monaco release, and which WebView2 Runtime and WebKitGTK minimum versions? No pin is in the docs.
7. Which WebView packages, and are their licences confirmed OSI-compatible? Doc 28 Conflicts 3 says needs counsel.
8. Which Linux route: `Avalonia.WebView` (community, unverified) or another free one? `NativeWebView` is excluded.
9. Which Linux session: X11 or Wayland? The research note proposes X11; Avalonia Wayland is opt-in.
10. Should doc 28's extra criteria (focus handoff to the native layer, memory per window, ready time, theme without reload) become criteria? The plan row does not include them, so they are recorded only.
11. The plan says "repeat three times" without a platform split. This runbook reads it as three per platform.
12. Paste uses the platform's standard shortcut. Does the no-Ctrl-chords rule for Bazaar commands cover this? Owner decides.
13. Which base commit does `spike/S12` start from, and do spike records reach main by PR (plan question 1, default yes)?
14. Conflict: the plan's fail row names AvaloniaEdit as the fallback, while C26 says the project may move off Avalonia. This runbook follows the plan row.
15. How is the bundle served to a non-file origin (virtual host mapping or a loopback server), and is loopback allowed under the offline test?
