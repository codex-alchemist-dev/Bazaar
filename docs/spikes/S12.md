# Spike S12: Monaco in a WebView, free routes only (Windows harness half)

Branch: `spike/S12` (code stays there; only this record reaches main). Design source: `docs/design/35-spikes-plan.md`, runbook `docs/spikes/runbooks/S12.md`.
Runner: Claude on the owner's PC (Windows client slice). Findings feed: docs 27, 28, 30; C23, C26.

## Question
Can Monaco load offline in a free WebView (WebView2 on Windows; WebKitGTK on Linux) with typing, IME, paste and theme working? Gate for the Avalonia decision (C26).

## Pass criteria (fixed before the first run)
Plan text: Monaco loads offline from bundled assets; typing, IME and paste work; theme applied; HWND fallback recorded if composition fails. Fail: AvaloniaEdit native editor, and the Avalonia decision is reopened. Pass needs both platforms (runbook s2).

## Time-box
3 d, hard stop. Not expired.

## Method
Windows 11 Pro build 10.0.26300; WebView2 Runtime 157.0.4341.60; Monaco 0.57.0 (MIT, pinned tgz, bundled as content files); .NET 11 (`net11.0-windows`); host is a WinForms `WebView2` control (not Avalonia; see limits). GPU: Intel Arc B580.

Harness: `S12Spike.exe`, a WinForms window with `SetVirtualHostNameToFolderMapping` of `https://s12.local/` to the bundled `web/` folder, `CoreWebView2HostResourceAccessKind.Deny`, and `NavigationStarting` cancelling every other origin. A visible window ran for 5 s; the owner approved visible test windows for S10 and S12 on 2026-11-18. The page loads Monaco through the AMD loader, creates an editor, calls `setValue`, reads it back, and posts the result to the host.

What the harness checks: Monaco loads from the bundle through a non-file origin (workers are allowed there); load time; `setValue` round trip.
What it does not check (the record must not claim these):
- Offline: the network adapter was not disabled. The only evidence is that all assets come from the virtual host and external navigation is blocked.
- Theme: `themeApplied` is set to `true` in the page without inspecting the editor, and `dark` only tests that a model exists. Neither is evidence. The theme criterion is not tested.
- Typing, IME and paste: need hands on the keyboard; not run.
- Linux (WebKitGTK): not run.

## Result
**inconclusive.** Monaco 0.57.0 loads from bundled assets in WebView2 through a virtual-host origin, and a value set from script reads back, in about 80 ms. That is only the load criterion, and without a network-off check. Theme is untested (harness bug above), typing, IME and paste are not run, the third run is not done, Linux is not run, and the host is WinForms, not Avalonia. No fail was observed, and nothing here passes the gate.

## Consequence
No DECISIONS-LOG entry. Avalonia stays conditional on S12 and docs 27, 28 and 30 are unchanged. Next: fix the theme check to read back computed colours, add the manual typing, IME and paste steps (runbook s7 steps 5 to 7) with the network adapter off, run three times, then run the Linux half.
